# Dogfood 4: 2026-11-21

Run 7 of migate's end-to-end runs; migate `a57046e`. How runs are judged, and the others: `README.md`.

A scripted pipeline replaced the agent: fixed cases, one frozen binary (checksum checked before each case), ground
truth before any migate run, every result scored by script. Its design was reviewed by a blind agent first, which found
five flaws (truth on a different database from migate's, a refused deploy scored as safe, data loss invisible, one
config for every era of history, a setup failure cached as a break); all were fixed before the full run, and the
calibration on five cases with known answers scored as expected.

migate's verdicts matched dogfood 3's on every case the two share. Median 224 s per case; no temporary folder or
worktree was left behind.

Of the six real migrations that added triggers, one broke the old version (70 of its API tests failed); the other five
are the false alarms a marker accepts.

Two results did not mean what they first seemed:
- **Syntax newer than production's engine:** blocked, but by MG803 (the local SQLite refused the statement too), not by
  MG701. MG701 scans only `.sql` migrations, so TypeScript, Python and Ruby migrations are never checked, while MG806
  says they are: TASK-78.
- **A blanked column without a seed:** scored as a miss, but the harness was wrong. Its control ran both test suites
  before counting; migate runs only the configured one, and that suite deletes its own rows, so migate's database held
  nothing to lose. The count must follow migate's own test command.
